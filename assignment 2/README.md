## Evidence and method

- Each timed case uses 3 warmups and 7 recorded repetitions with System.nanoTime().
- `results/raw.csv` preserves each batch duration, operation count, checksum and heap occupancy snapshots; REPORT.md derives mean, median, standard deviation and mean ns/op.
- Setup is excluded. Timing measures educational workloads in one JVM per task, with fixed case order and no multi-fork JMH isolation. JIT, GC and host scheduling can distort results; Big-O is derived from operations, not inferred solely from finite timing points.
- `output.txt` is the actual stdout transcript. `output-*.png` are browser screenshots of those captured transcripts, generated by headless Chrome when available. They are labelled as rendered transcripts; they are not claimed as screenshots of a student's local terminal.
- `environment.txt` records Java, OS/CPU metadata, timestamp, runner and source commit. Automated evidence is from a GitHub runner, not from the student's personal computer.
- Q7 instruments actual sorting comparisons and checks exact report contents. No timing data is hard-coded or invented.

The GitHub Actions workflow compiles and executes all tasks, generates the report/screenshots, uploads an evidence archive, and commits results back to this repository. Its log is additional verifiable execution evidence. The workflow has a 20-minute limit and no recurring schedule.
